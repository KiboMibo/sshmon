**Дата:** 2026-08-01 · **Ветка:** `main` @ `7afeebd` · **Метод:** статическое чтение кода 4 агентами + сверка с макетами `sshmon-Design.pdf` (экраны 3a–3f) и прошлыми отчётами `analysis/sshmon/{ASSESSMENT,SECURITY}.md`.

> **Ограничение прогона.** Собрать и прогнать тесты не удалось ни в облаке, ни на вашей машине: `go.mod` требует Go 1.26.5, в контейнере есть только 1.24.7, а `proxy.golang.org` и `dl.google.com` закрыты сетевой политикой; на смонтированной машине Go нет вовсе. ## 1. Краткий вывод

Кодовая база здоровая: слои чистые, циклов нет, CI есть (gofmt/vet/build/test + govulncheck), 5 из 10 пунктов прошлого техдолга закрыты. Проблемы сосредоточены в трёх местах:

1. **Экран «полный экран сервера» (макет 3c) реализован не по макету** — метрики не на одной сетке, спарклайнов нет вовсе, DOCKER/СЕРВИСЫ/ПОРТЫ в рамках вместо разделителя, клавиши `l`/`x` из статусбара не работают.
2. **Четыре дефекта, которые видны пользователю в бою** — разрыв SSH-соединения при выходе из логов, потеря нижней половины экрана на терминале высотой 16–20, битые ANSI при обрезке строк, ящик логов показывает чужие логи после `j/k`.
3. **`internal/tui` вырос, а не уменьшился** — 34 файла / 4398 LOC против 27 / 3272 в прошлом ассессменте. Заготовленный шов (`screen.go`) применён к 3 экранам из 7.

### 2.2. Экраны флота (3a, 3b, 3d)

- **F1 (блокирующее).** В макете 3b при раскрытии по `→` сайдбар уступает место деталям. В коде `renderFleetWide` (`fleet.go:147-173`) рисует сайдбар безусловно, а раскрытая карточка вклеивается внутрь узкой левой колонки (`fleet.go:190-192`) — компоновка принципиально иная.
- **F2 (блокирующее).** Раздела «ТОП ПО ПАМЯТИ» из макета 3a нет вообще: ни данных, ни рендера (`fleet_detail.go:17-38` — только статус, «ЧТО НЕ ТАК», «ДЕЙСТВИЯ»).
- **F3 (существенное).** Колонка «СОСТ» показывает только глиф без текста; готовая `statusText()` (`fleet.go:290`) — мёртвый код. Ремарка на макете прямо требует «работает и без цвета». Там же: заголовок колонки «ИМЯ» вместо «ХОСТ», нет маркера `▍` слева у выделенной строки (`fleet.go:78-83` — только фон).
- **F4 (существенное).** «ДЕЙСТВИЯ» в сайдбаре: код показывает `enter · / поиск · f проблемные`, макет — `enter детали · l логи · p процессы · x ssh` (`fleet_detail.go:30-36`).
- **F5.** Нет общей рамки «ГРУППЫ» вокруг плиток (`fleet_card.go:130-136`). В широком режиме нет единого статусбара — подсказки развезены по нижним границам панелей (`fleet.go:164-171`).
- **F6.** Ящик логов: нет счётчика «12 новых» (`fleet_logbox.go:36-51`); поле `lastLineAt` (`logs.go:38`) заведено и не используется. Формат статуса «system · all · хвост включён» вместо «postgres · warn+ · хвост вкл».
- **F7.** UPTIME выводится как `140d5h` латиницей (`fleet.go:300-309`), макет — `140д`.
- **F8.** Колонки UPTIME/DOCKER показываются всегда; по макету они появляются только в режиме деталей (3b), в 3a их нет.

### 2.3. Полноэкранные логи (3e) и подсказки (3f)

- **L1 (блокирующее).** Список источников логов всегда состоит из одного элемента: `m.logs.sources` инициализируется как `[{LogSystem}]` (`logs.go:57-65`) и никогда не пополняется. Значит ось «источник `[postgres] docker/api-worker systemd nginx`», `cycleLogSource`, хинты `← →` и клавиша `x` — неработающий UI.
- **L2.** Нет полосы «плотность» со всплесками, нет подсветки выделенной строки, нет `y копировать`, `c контекст ±5`, `n/N след/пред`, `t время`.
- **L3.** `w` в макете — переключатель «только warn+», в коде — циклический перебор уровней `all→info→warn→error` (`logs.go:172-175`).
- **H1.** Оверлей справки закрывается только по `esc`, хотя сам пишет «esc / ? — закрыть» (`overlays.go:94-122`, `help.go:134`) — баг относительно собственной подсказки.
- **H2.** В справке для fleet нет `gg G` и `space` (пауза автообновления) — таких биндов нет в `navigation.go` вовсе; `r` (обновить) на fleet не работает (`navigation.go:69` — только dashboard).

### 2.4. Дыра в дизайне

Макет описывает **одну** раскладку. Код содержит два принципиально разных рендера: широкий (`dashboard_server.go`, соответствует 3c) и узкий (`dashboard_view.go:19-36`) — с другими заголовками («SYSTEMD» вместо «СЕРВИСЫ»), другими колонками docker и логами, урезанными до 2 строк. Порог — `width >= 100` (`layout.go:6`). Для терминала 80 колонок дизайна не существует; ремарка на последней странице PDF («покажи 3a на 80 колонках») это подтверждает — вариант ещё не нарисован.

## 3. Дефекты реализации

### Блокирующие

**B1. На терминале высотой 16–20 нижняя половина экрана сервера пропадает молча.**
`dashboard_server.go:22`: `budget := max(8, m.layout.height-len(lines)-5)`. Пол `8` игнорирует реальный остаток; плитки всегда занимают ≥11 строк. При 100×16 `wide=true` (`layout.go:21`), `layout.height=14`, шапка+метрики съедают 13–16 строк, тело выходит на 28 строк, а `composeScreen` (`panels.go:82`) режет **хвост** — СЕРВИСЫ, ПОРТЫ, DOCKER и ЛОГИ не выводятся вообще и без каких-либо признаков обрезки. Тесты покрывают только 120×30 и 160×50.

**B2. `fitLine` рвёт ANSI-последовательности.**
`panels.go:94`: ширина считается через `lipgloss.Width` (escape-коды не учитываются), а обрезка идёт по `[]rune`, включая байты escape. Итог: либо срезается финальный `\x1b[0m` и остаток кадра красится в dim (футер fleet на 80 колонках — `fleet.go:137`), либо обрезка останавливается внутри `\x1b[33m` из `highlightMatches` и терминал съедает следующие байты. Тесты проверяют только `lipgloss.Width(line) <= w` и этого не ловят. Правка — `ansi.Truncate` из `charmbracelet/x/ansi` (уже в зависимостях).

### Важные

**B3. Выход из логов рвёт общее SSH-соединение сервера.** `sshx/stream.go:56-62`: `closeStream` всегда вызывает `drop()`, который закрывает весь `ssh.Client`, а не сессию. Любой `esc`, смена источника или штатный EOF → следующий тик сборщика метрик делает полный re-dial и handshake (а с passphrase-ключом без агента — ещё и запрос парольной фразы).

**B4. То же при отмене диагностики.** `sshx/sshx.go:174`: `runCommand` по `ctx.Done()` вызывает `drop()`. Открыл «Процессы», нажал `esc` до ответа — соединение закрыто.

**B5. `j/k` в ящике логов меняют сервер, но не поток.** `fleet_logbox.go:26` не перехватывает `j/k`, управление уходит в `moveFleetBy` (`navigation.go:36`), стрим остаётся на прежнем хосте, а заголовок ящика уже показывает новый (`fleet_logbox.go:50`). Оператор читает чужие логи под чужим именем.

**B6. Палитра «Сервер: X» не перезапускает workspace.** `palette.go:99` меняет `m.selected` и `m.screen` без `cancelDashboardWorkspace()`/`startDashboardWorkspace()` — контейнеры, юниты и логи остаются от предыдущего сервера.

**B7. Выход только с экрана Fleet.** `navigation.go:170`: `q`/`ctrl+c` под `if m.screen == screenFleet`. На логах/истории/дашборде ctrl+c ничего не делает (bubbletea в raw-режиме сам SIGINT не шлёт).

**B8. Глубокие экраны не прокручиваются.** `processes.go:66`, `ports.go:70`, `containers.go:61` печатают все строки, хвост режется `composeScreen`; `up/down/pgup/pgdown` обработаны только для fleet. 200 процессов на 24 строках — видно первые ~19. Поля `s.sort` не присваиваются нигде в непроверочном коде.

**B9. Спарклайн истории для NET и Load бесполезен.** `panels.go:39` клампит значения в `[0,100]`, считая их процентами, но `historyMetricNetRX/NetTX/Load1` — байты/с и load average: 8 КБ/с → сплошной `█`.

**B10. Утечка контекста при смене глубокого экрана через палитру.** `requests.go:103`: `cancelDiagnostics()` отменяет только текущий `m.screen`; «Процессы» → палитра → «Порты» оставляет контекст процессов неотменённым.

### Мелкие

- Мёртвый код: `sparkline()`, `deviceTables`/`diskTable` (`dashboard.go:83,104`), `dashboardNetworkContent` (`dashboard_panel.go:179`), `overlayTitle`, `renderDeepPlaceholder`, `statusText`, поле `Model.llm` (`model.go:16`).
- Недостижимые ветки: `dashboard_view.go:112,122` (условия на `layout.wide` внутри функций, вызываемых только из narrow-ветки).
- `diskBars` режет точку монтирования по байтам (`dashboard_metrics.go:64`, `mount[:12]`) — битая руна на кириллическом пути.
- `truncateCells` без защиты при `width <= 1` (`fleet.go:326`).
- Запрос passphrase затирает открытый оверлей без `closeOverlay()` (`reconnect.go:52`).
- `lipgloss.Style.Copy()` — deprecated в v1.x, 4 вызова.

### 4.2. Новое

- **Протечка слоя `tui → sshx`** (в прошлом ассессменте её не было): `collect.StreamLogs` возвращает транспортный тип `sshx.Stream` (`collect/logs.go:41`), поэтому `internal/tui/logs.go:19-21,35` импортирует `sshx`, а `reconnect.go:54` матчит sentinel'ы `sshx.Err*`. Лечится тонким `collect.LogStream` + собственными ошибками `collect`.
- **`LogBuffer.Append` — O(n) на строку** после заполнения: `b.lines = append([]string(nil), b.lines[excess:]...)` копирует все 10 000 строк на каждую новую (`collect/logs.go:155-159`).
- **Passphrase проходит через Go-строку** и не зануляется: `reconnect.go:62-75` зануляет только копию `[]byte`, исходная строка и буфер `textinput` остаются в куче — расходится с выводом SECURITY.md.
- **Подписка снимается только на пути `q`** (`model.go:219-224`); при выходе по сигналу канал остаётся в `c.subscribers`.
- **Аргумент-инъекция в `ssh`**: `fleet_actions.go:59,72-84` кладёт `server.Host` в argv без валидации, `config.Load` не запрещает ведущий `-` — host вида `-oProxyCommand=…` из импортированного `~/.ssh/config` будет разобран ssh как опция. Низкая, но реальная.
- **`Reconnect` игнорирует родительский контекст** (`collector.go:140` — `context.Background()`).
- **`pollAndPublish` делает `Snapshot()` дважды** при наличии sink (`collector.go:73,83`) — двойной проход `issuesLocked` на каждом тике.
- **CI:** есть `gofmt`/`vet`/`build`/`test` + `govulncheck`, релиз сверяет `buildinfo.Version` с тегом. Пробелы: нет `go test -race` (при том что `collect`/`LogBuffer`/`sshx` многопоточные), `govulncheck@latest` не запинен, actions по плавающим мажорам.
- **ADR по-прежнему нет** — решения (ручной MCP вместо SDK, pure-Go SQLite, sync-over-async writer) нигде не зафиксированы.
- **`demo/config.yaml:8-10`** содержит `password: demo` + `insecure_host_key: true` — это демо, но шаблон скопируют.

### 4.3. Предлагаемая нарезка `internal/tui`

Порядок важен — сначала то, что не зависит от `Model`:

0. `internal/tui/theme` — `styles.go` + `layout.go` + `panels.go` + `sparkline.go`. Чистые функции, ноль зависимостей от `Model`.
1. `internal/tui/state` — `diagnostics*`, `layoutState`, `screenKind`, `overlayKind`.
2. В `collect` — свой `LogStream` и свои sentinel'ы: снимает ребро `tui → sshx` **до** разъезда экранов по пакетам.
3. Расширить `screenContext` до реального read-only среза (`snapshot`, `layout`, `selected`) и довести `screen` до `view(ctx) string` + `update(ctx, msg) (screen, tea.Cmd)`. Сейчас `update` живёт в `Model` — это главный блокер. Пилот: `logs` и `history` (уже почти самостоятельны).
4. Пакеты по кластерам: `deep` (processes/ports/containers, 212 LOC — самый дешёвый первый), затем `logs` (367), `histview` (214), `dashboard` (1089), `fleet` (1001), `overlay` (522). Корневой роутер (`model.go` + `navigation.go` + `messages.go`, ~470 LOC) остаётся как есть.

Что мешает: 22 из 34 файлов объявляют методы на `Model`; общие глобальные стили; цикл `fleet ↔ dashboard` (`fleet_actions.go:38-52` ↔ `navigation.go:127-154`) — лечится `navigateMsg{to}` через корневой роутер; `requests.go:100,112` держит конкретный `*collect.Collector` — нужен интерфейс по образцу `dashboardSource`.

## 5. Что предлагаю делать

**Волна 1 — дефекты, видимые в бою** (не требует решений по дизайну): B1, B2, B3, B4, B5, B6, B7, B10 + мелочи (мёртвый код, `diskBars`, `truncateCells`, `closeOverlay`).

**Волна 2 — экран сервера по макету 3c:** единая метрическая сетка CPU/MEM/NET/DISK со спарклайнами (C1, C2), клавиши `l`/`x`/`r` и статусбар (C3), счётчики в заголовках и формат контейнеров (C5, C6), строка состояния логов (C8).
