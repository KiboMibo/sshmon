## 1. Главное ограничение прогона

Собрать проект штатным образом было невозможно: `go.mod` требует Go 1.26.5, в контейнере доступен 1.24.7, сеть до `proxy.golang.org` и `dl.google.com` закрыта, на машине пользователя Go нет вовсе.

Чем это компенсировано:

| Проверка | Как сделана | Статус |
|---|---|---|
| Синтаксис всех файлов | `gofmt -l -e ./internal ./cmd` после каждой правки | чисто |
| Дубли объявлений, неразрешённые вызовы уровня пакета | самописный анализатор на `go/ast` (stdlib-тулчейн 1.24) | чисто |
| **Компиляция и `go vet`** | проверяющий собрал стаб-модули для всех внешних зависимостей, скопировал дерево с `go 1.24` и `replace` на стабы; настоящий компилятор прошёл 10 пакетов / 116 файлов, включая тесты. Харнесс проверен на подставных ошибках (`var s string = 5`, вызов несуществующего метода, `printf`, `stringintconv`) — ловит | **BUILD OK, VET OK** |
| `go test` | под стабами исполнимы `internal/collect` и `internal/mcpsrv` — **проходят**. `internal/tui` под стабами неисполним (фейковые `lipgloss`/`bubbletea`) | частично |
| Гонки (`-race`), реальный прогон тестов TUI, поведение в терминале | **не проверялись** | остаётся на CI и на ручной прогон |

**Вывод по готовности:** код собирается и проходит `vet` по независимой проверке настоящим компилятором; тесты пакета `internal/tui` (их 30+ новых и переписанных) ни разу не исполнялись. Это главный остаточный риск, и закрывается он первым же прогоном CI на PR.

## 2. Что сделано по волнам

### Волна 1 — дефекты, видимые в бою

Три исполнителя параллельно по непересекающимся файлам (`w1-transport`, `w1-nav`, `w1-render`), затем задача исправления `F1` по итогам ревью.

- **Выход из логов больше не рвёт SSH-соединение сервера.** `closeStream` закрывал весь `ssh.Client`, а не сессию; каждый `esc` из логов заставлял следующий тик метрик делать полный re-dial и handshake (а с passphrase-ключом — заново спрашивать фразу). То же исправлено для отмены диагностики. `drop()` теперь вызывается только при транспортной ошибке (`isTransportFailure`), и наоборот — транспортная ошибка теперь действительно инвалидирует кэшированный клиент.
- **Частичный вывод при транспортной ошибке больше не считается успехом** — коллектор не запишет обрезанный сэмпл как `Online: true` с мусорными дельтами.
- **`LogBuffer.Append`** был O(n) на строку после заполнения (копия 10 000 строк на каждую новую) — стал кольцевым с амортизированной компактизацией.
- **`Snapshot()`** клонирует слайсы `Disks/IO/Net/Ports`; контракт вынесен в публичный docstring. Контракт `Subscribe` (вытеснение старого события) задокументирован.
- **ANSI-безопасная обрезка строк** (`fitLine`): раньше обрезка шла по рунам, включая байты escape-последовательностей — срезался финальный сброс стиля и остаток кадра красился в dim, а обрыв внутри `\x1b[33m` заставлял терминал съедать следующие байты.
- **`ctrl+c` завершает приложение с любого экрана** и из-под оверлеев и полей ввода; раньше выход работал только на экране флота.
- **`j/k` в ящике логов** переключают и хост, и поток (раньше заголовок показывал новый хост, а строки шли от старого); при смене хоста и источника буфер очищается.
- Отмена диагностики снимает все виды, а не только текущий экран; палитра «Сервер: X» перезапускает workspace; справка закрывается по `?`, как и обещает; запрос парольной фразы не затирает открытый оверлей и не плодит копий секрета.
- **Новая раскладка клавиш по макету:** `l` логи, `x` ssh, `s` источник логов, `h` история, `r` обновить, `ctrl+r` переподключить; `ctrl+l`/`ctrl+h` остались алиасами.
- **Новые данные:** дистрибутив ОС (`/etc/os-release`, зонд уходит один раз на сервер) и uptime контейнера (`docker ps --format {{.RunningFor}}`).

### Волна 2 — полный экран сервера по макету 3c

- **Единая метрическая сетка** `CPU / MEM / NET / DISK` вместо четырёх разнородных блоков: одна ширина метки, спарклайна и колонки процента, детали справа выровнены по общей границе. MEM и DISK — заливка текущего процента, CPU — живой спарклайн тренда (кольцо на 60 точек в модели, обновляется каждым снапшотом), NET — без процента.
- **Ряд `DOCKER | СЕРВИСЫ N + ПОРТЫ N`** со счётчиками в заголовках; строка контейнера — имя, человекочитаемый статус, аптайм (`140д`), абсолютная память вместо процентов.
- **Шапка** — `имя · ● норма · группа · адрес · debian 12 · 8 ядер · 15.6G · up 140д`, свежесть данных переехала в правый край статусбара.
- **Честная деградация по высоте.** Раньше на терминале 100×16…20 нижняя половина экрана (СЕРВИСЫ, ПОРТЫ, DOCKER, ЛОГИ) молча не выводилась. Теперь три ступени раскладки (колонки → стопка → компакт), приоритет сворачивания единый, усечение помечается явно; логи занимают остаток высоты, как требует макет.
- **Раскладки wide/narrow сведены к одной адаптивной** (решение D3), внешняя рамка экрана убрана (D4), удалено 26 мёртвых символов.

### Волна 3 — флот и полноэкранные логи

- **Сайдбар уступает место деталям** при раскрытии по `→` (макет 3b).
- **Раздел «ТОП ПО ПАМЯТИ»** — топ-3 процессов выбранного хоста через существующий механизм диагностики, с отменой предыдущего запроса и дебаунсом.
- **Колонка `СОСТ` с текстом**, а не только глифом (`● норма`, `⚠ память 98%`, `× нет связи`), маркер `▍` у выделенной строки — выделение читается без цвета, как требует ремарка макета. Заголовок `ХОСТ`, рамка `ГРУППЫ`, единый статусбар внизу вместо подсказок на рамках панелей.
- **Колонки UPTIME/DOCKER** появляются только в режиме деталей и первыми уходят при нехватке ширины; uptime в формате `140д`.
- **Ящик логов:** счётчик `12 новых · 214 из 8 412`, формат состояния `postgres · warn+ · хвост вкл`, список хостов под ящиком больше не срезается.
- **Полноэкранные логи по макету 3e:** источники наполняются из systemd-юнитов и docker-контейнеров выбранного сервера (раньше список всегда состоял из одного элемента, а весь UI переключения был неработающим); три оси фильтрации со счётчиком `214 из 8 412 строк`; полоса плотности со всплеском; выделенная строка, контекст ±5, `n/N`, `t`, копирование через OSC 52 без новых зависимостей; `w` стал toggle «только warn+», перебор уровней — на `W`.
- Прокрутка списка флота в одноколоночном режиме, `home`/`end`, постраничная прокрутка на живом потоке, один проход по буферу за кадр вместо трёх.

### Волна 4 — архитектура

- **Снята протечка слоя `tui → sshx`**: `collect` получил свой `LogStream` и sentinel-ошибки; в пакете `tui` не осталось ни одного упоминания `sshx`.
- **CI:** добавлен `go test -race`, `govulncheck` запинен на версию.
- **ADR** (`docs/architecture/`): ручной MCP-протокол, pure-Go SQLite, переиспользование SSH-соединения и политика инвалидации, единая адаптивная раскладка, отложенное разрезание `internal/tui`.
- **`CLAUDE.md`** — карта репозитория для кодинг-агентов; **раздел «Операции»** в README (офлайн-сервер, где лежат конфиг и база, ротация ключа LLM, снятие диагностики); предупреждение в `demo/config.yaml`; убраны deprecated-вызовы `lipgloss.Style.Copy()`.

### Секьюрити-правки (по итогам финального ревью)

- **Санитизация текста с удалённого хоста (CWE-150).** Строки логов, вывод `ps`/`ss`/`docker`, имена юнитов и контейнеров, текст ошибок ssh шли в терминал оператора как есть. Процесс на мониторимом хосте мог записать в свой лог `\x1b]52;c;<base64>` и молча переписать буфер обмена оператора — без единого нажатия клавиши; тем же способом подделываются статусбар и заголовок окна. Санитизация поставлена **на входе, в `collect`** — те же строки MCP-сервер отдаёт наружу другим клиентам, чей терминал мы не рисуем. Собственная стилизация накладывается строго после.
- Ограничена длина полезной нагрузки OSC 52 (до 4 КБ вместо возможного 1 МБ).
- Дебаунс запросов `ps` и перезапуска потока логов — удержанная стрелка больше не порождает поток SSH-каналов.

## 4. Сознательные расхождения с макетом

| Что | Почему |
|---|---|
| `restarting (×4)` показывается как `restarting` | `docker ps` не отдаёт счётчик рестартов; число в скобках — код выхода, выдавать его за счётчик нельзя |
| СЕРВИСЫ и ПОРТЫ — две плитки, а не две колонки одного блока | следствие решения D4 сохранить рамки плиток |
| Рамки плиток сохранены, убрана только внешняя рамка экрана | решение D4 |
| ПОРТЫ скрываются при бюджете тела ≤ 9 строк | арифметика: паре плиток нужно 6 строк, логам — минимум 3 |
| Текст состояния хоста берётся из `Issue.Msg` («память 98%»), а не «mem 98%» | сообщения формирует коллектор; менять их — отдельное решение по терминологии |
| В логах нет разбивки на колонки «время · уровень · процесс · сообщение» | требует парсинга формата каждого источника; в постановку волны не входило |
| Подсказка плитки логов — `l логи · s источник` вместо `/ фильтр · x источник` | `x` теперь ssh, `/` на экране сервера — поиск серверов |

## 5. Отложено

- **Разрезание `internal/tui` на подпакеты** (шаги 0, 1, 3, 4 из плана) — зафиксировано в `docs/architecture/0005-tui-package-split-deferred.md`. Причина: без компилятора межпакетный рефакторинг 4400 LOC почти гарантированно ломает сборку. Шаг 2 (снятие ребра `tui → sshx`) выполнен.
- i18n / вынос строк — пункт 10 прошлого ассессмента, не закрыт.
- Пин `actions/*` на commit SHA в CI — из этой сессии GitHub API недоступен, выдуманный SHA положил бы CI.
- Аргумент-инъекция в `ssh` через `Host` вида `-oProxyCommand=…` из импортированного `~/.ssh/config` (низкая, из прошлого аудита) — не бралась в объём.
- Дизайн узкого режима (80 колонок) не рисовался: код сведён к одной адаптивной раскладке, но макета для проверки нет.

## 6. Что должен подтвердить CI

1. `go build ./...`, `go vet ./...` — по независимой проверке проходят, но на настоящем toolchain 1.26.5 и настоящих зависимостях не запускались.
2. `go test ./...` — **главный пункт**: тесты `internal/tui` (30+ новых и переписанных) не исполнялись ни разу.
3. `go test -race ./...` — впервые добавлен в CI, первый прогон может вскрыть реальные гонки в `collect`/`sshx`; это цель, а не регресс.
4. Совместимость `bubbles v1.0.0`: прямые присваивания `viewport.Width/Height/YOffset` и `viewport.New(w, h)`. По документации это API ветки до v2, риск низкий; неподтверждаемый вызов `SetYOffset` из кода убран специально.
5. `gofmt -l .` — локально чисто.
